# ファーストビュー制作プロンプト

PLAID ALPHA / Goodpatch Anywhere / Muturelism Conference / neu / 名古屋たちばな高等学校マーチングバンド部
のような「タイポグラフィと図形そのものが世界観になる」サイトの、ファーストビューを作るためのプロンプトです。

- 使い方:`【 】` の部分を案件の内容に書き換え、下の「プロンプト本文」をまとめてAIに渡す。
- 参考サイトは**完成度の基準**として扱う。見た目やコードの模倣はさせない。
- 次の段階(2セクション目以降)では、ここで決めた「デザイン言語」をそのまま引き継ぐ。

## プロンプト本文

```
あなたは、国内外のアワード受賞レベルのWebサイトを手がけるアートディレクター兼クリエイティブ
エンジニアです。以下のブランドのWebサイトの「ファーストビュー(最初の1画面+スクロール開始直後)」
だけを、本番品質で設計・実装してください。

# 1. ブランド情報
- 名前:【サイト名 / ブランド名】
- 何をしているか:【一文で】
- 届けたい相手:【ターゲット】
- 最初の3秒で感じてほしいこと:【例:大胆さ・知性・温度感】(形容詞3つまで)
- メインコピー:【日本語コピー】/ サブ:【英語のキーワードやタグライン】
- 使える素材:【ロゴSVG / 写真 / 動画 / なし】
- ブランドカラー:【HEX、なければ「提案して」】

# 2. 品質の基準(参考サイト)
次の5サイトを完成度の基準にします。見た目、構図、コードはコピーしないでください。
「何がそのレベルを支えているか」を取り込み、このブランドに合わせて組み直してください。

| 参考 | 取り込む本質 |
|---|---|
| PLAID ALPHA | 画面からはみ出すほど大胆なスケール。文字・図形・余白の三つを等価に扱う構成 |
| Goodpatch Anywhere | 抽象的な形と文字を「別々の要素」ではなく一つのグラフィックとして組む |
| Muturelism Conference | 1px級の繊細な線。性質の違う形を線でつなぐ。細部まで同じルールで統一された世界観 |
| neu | 文字そのものを主役のビジュアルにする。奥行き、重なり、立体感 |
| 名古屋たちばな高校 マーチングバンド部 | 画面全体を一つの世界として見せる。レイヤーの奥行き、記憶に残る登場の演出 |

この5つから取り込むのは、次の5つの要素です。
1. **スケールの振れ幅**:ビューポート幅の60〜120%を占める巨大な要素と、11〜13pxの小さな注記を同じ画面に置く。
2. **文字=図形**:メインコピーかロゴタイプのどちらかを、図形・線・レイヤーと組み合わせてキービジュアルにする。
   文字の上に画像を置いただけのヒーローにはしない。
3. **線のシステム**:ヘアライン(0.5〜1px)を1本のルールで使い分ける。グリッド、つなぎ線、目盛り、注記の引き出し線などに使う。
4. **奥行き**:前景・中景・背景の3層以上。スクロールとポインタの動きに対して、層ごとに違う速度で反応させる。
5. **統一**:角丸、線の太さ、イージング、余白の単位、色数を最初に決め、例外を作らない。

# 3. 最初にやること(コードを書く前)
次の内容を短く出してください。出したら、そのまま実装に進んでください。
- コンセプト:一行のコンセプトと、それを形にする「ビジュアルのアイデア」1つ。
  (例:「響きが広がる」→ 同心円の線とメインコピーの文字が、音の波紋のように重なって広がる)
- デザイントークン:色(最大でベース2色+アクセント1色)、書体、文字サイズのスケール、余白の単位、
  線の太さ、イージング、時間の単位。
- レイアウトのスケッチ:1440×900とモバイル375×812のそれぞれで、何をどこに置くか(ASCII図でよい)。
- モーションのタイムライン:表示開始から操作できるようになるまでを、ミリ秒単位で書く。

# 4. デザイン要件
## タイポグラフィ
- 和文と欧文の書体を組み合わせる。
  和文は【例:Noto Sans JP / Zen Kaku Gothic New / Shippori Mincho】、
  欧文は【例:Inter Tight / Instrument Serif / Space Grotesk】。Google Fontsなど、ライセンスが明確なもの。
- メインの見出しは clamp() で流体的なサイズにする。デスクトップでは 12vw 以上を目安に、画面の端で切れてもよい。
- 字間、行間は和文と欧文で個別に調整する。巨大な文字は字間を詰め、小さな注記は字間を広げて大文字にする。
- 大きな文字はSVGか、文字単位に分割したDOMにする。1文字ずつ、または線単位でアニメーションできる状態にする。

## 構成
- 12カラムのグリッドを下敷きにし、メインのビジュアルだけ意図的にグリッドから外す。
- 画面の四隅に情報を置く(ロゴ、ナビゲーション、日付や番号、スクロールの案内)。中央を広く空けて「間」をつくる。
- 余白は飾りではなく構成要素として扱う。要素を詰め込まない。

## 図形と線
- 抽象図形(円、半円、矩形、角丸、曲線など)は、ブランドの意味から導いた2〜3種類に絞る。
- 図形同士、図形と文字をヘアラインでつなぎ、「関係性」が見えるようにする。
- 塗りより線を多くして、上品さと緊張感を保つ。

## 立体感と奥行き
- 次のどれか1つを主役にする(全部は使わない)。
  a) CSSの3D(perspective / translateZ)で文字を何層にも重ねる
  b) SVGの文字にオフセットした複製を重ね、押し出した立体のように見せる
  c) Three.js / WebGLで文字や図形をシーンに置く(使う場合は、静止画で表示できるフォールバックを用意する)
- 背景にはノイズ、グレイン、グラデーションを薄く敷き、画面が平板にならないようにする。

# 5. モーション要件(最重要)
動きは「飾り」ではなく「世界観の説明」として設計してください。

## オープニング(合計 2.0〜3.5秒)
1. 0ms〜:背景とヘアラインのグリッドが描かれる(stroke-dashoffset)。
2. 〜800ms:主役の図形が、生まれる・広がる・組み上がる。
3. 〜1600ms:メインコピーが1文字ずつ、または行ごとにマスクから現れる。stagger は 30〜60ms。
4. 〜2400ms:四隅の小さな情報とナビゲーションがフェードインする。操作できる状態にする。
- イージングはすべて共通の1〜2種類にする(例:cubic-bezier(0.22, 1, 0.36, 1))。
- 2回目以降の訪問(sessionStorageで判定)では、オープニングを短縮版(1秒以内)にする。

## 待機状態(何も操作していないとき)
- 画面を完全には止めない。ゆっくりした呼吸のような動き(回転、うねり、明滅など)を、
  周期6〜12秒・振れ幅小さめで続ける。

## ポインタ
- マウスの位置に応じて、層ごとに違う量だけ視差移動させる(前景 > 中景 > 背景)。lerpでなめらかに追従させる。
- メインの文字や図形が、カーソルに近づくと少しだけ反応する(線が伸びる、文字が少し傾くなど)。

## スクロール(0〜100vh)
- スクロールの進み具合に合わせて、キービジュアルが拡大・分解・回転しながら次のセクションへつながる。
  スクロールを使った演出は、ファーストビューの範囲内だけにとどめる。
- 慣性スクロール(Lenisなど)を使う場合は、ネイティブのスクロールとアンカーリンクを壊さない。

## アクセシビリティ
- prefers-reduced-motion: reduce のときは、オープニング、視差、待機中の動きをすべて止め、完成状態の静止画を表示する。
- 動きでしか伝わらない情報を作らない。

# 6. 技術要件
- 構成:【例:HTML/CSS/JS 単体 or Vite + TypeScript or Next.js】。
  モーションは GSAP(+ScrollTrigger)か、Web Animations API で実装する。
- 60fpsを保つ。アニメーションさせるのは transform / opacity / stroke-dashoffset だけにする。
  レイアウトが動くプロパティは使わない。
- LCPの要素(メインの見出し)は、JavaScriptの読み込みを待たずに表示する。最初は見える状態にしておき、
  JavaScriptで初期状態に戻してから演出する。
- フォントは preload と font-display: swap を指定し、必要なら和文をサブセット化する。
- レスポンシブ:1440 / 1024 / 768 / 375 のそれぞれで「構図として成立する」こと。
  モバイルでは縮小ではなく再構成する(縦の構図、巨大な文字の改行位置を変える、など)。
- タッチ端末ではポインタの演出を、ジャイロかゆっくりした自動の動きに置き換える。
- セマンティックなHTML。h1は1つ。装飾のSVGには aria-hidden を付ける。

# 7. 自己チェック(納品前に必ず実行)
Playwrightなどで次の時点のスクリーンショットを撮り、自分で見て評価してください。
撮る時点:オープニングの 0.5s / 1.5s / 3s / 完了後、スクロール 30%・100%、375px幅、reduced-motion。
その上で、次の観点をそれぞれ10点満点で採点し、8点未満の観点は直してから提出してください。
- スケール:一目で「大胆」と言えるか。安全なサイズに収まっていないか。
- 一体感:文字と図形が一つのグラフィックになっているか。
- 細部:線の太さ、余白、イージングが統一されているか。例外はないか。
- 奥行き:層が3つ以上あり、動かしたときに空間を感じるか。
- 記憶に残るか:スクリーンショット1枚で、このブランドだとわかるか。
- 動きの質:カクつき、ちらつき、レイアウトのずれ(CLS)はないか。

# 8. 出力
1. コンセプト、デザイントークン、レイアウトのスケッチ、モーションのタイムライン(セクション3の内容)
2. 実装コード一式(そのまま動く状態)
3. 自己チェックの結果(スコアと、直した内容)
4. 次のセクションへ引き継ぐ「デザイン言語の要約」(10行以内)
```

## 補足:プロンプトを書き換えるときのポイント

- **形容詞は3つまでに絞る。**「大胆・知的・温かい」のように絞ると、AIが判断に迷わない。
- **主役の立体表現は1つにする(4章 a/b/c)。** 全部使うと散らかり、参考サイトの「統一」から遠ざかる。
- **ミリ秒単位のタイムラインを先に書かせる。** 先に書かせることで、動きが場当たりにならない。
- **自己チェックのスクリーンショットは削らない。** 完成度を最も左右するのがこの工程。
